# Telegram-бот мебельной мастерской Larisel

Бот под ключ для производителя мебели: клиент собирает кресло прямо в чате,
видит цену в реальном времени, смотрит выбранную модель в 3D и оформляет заказ.
Владелец получает заявку в Telegram мгновенно и ведёт заказы из встроенной
админ-панели.

Демо-проект: показывает, как я делаю ботов на заказ.
Связка с [3D-конфигуратором на Three.js](https://larisel.com/mobilya/) —
бот и 3D-сцена работают с одним каталогом и считают цену по одной формуле.

---

## Что умеет

**Клиент**

- 🪑 Конфигуратор кресла: 6 тканей, 4 каркаса, 2 размера, декоративная подушка
- 💰 Пересчёт цены на каждое нажатие, срок изготовления и дата готовности
- 🌐 Кнопка «Посмотреть в 3D» — переход в интерактивный конфигуратор
- 🛒 Корзина: несколько сборок одновременно, изменение количества, удаление
- 📝 Оформление заказа за 5 шагов с проверкой каждого поля
- 📞 Телефон кнопкой «Отправить контакт» или вручную в любом формате
- 📦 История заказов и текущий статус
- 🔔 Уведомление клиенту при смене статуса

**Администратор**

- 🔔 Мгновенное уведомление о новом заказе со всеми контактами
- 📊 Статистика: заказы, выручка, пользователи, активные корзины
- 📋 Список заказов с постраничной навигацией и фильтром по статусу
- 🔄 Смена статуса в один тап (6 статусов), клиент узнаёт автоматически
- 📥 Выгрузка всех заказов в Excel и CSV прямо в чат

## Технологии

| | |
|---|---|
| Язык | Python 3.11+ |
| Фреймворк | aiogram 3 (async, FSM, CallbackData, мидлвари) |
| Хранилище | SQLite (стандартный `sqlite3`, WAL, транзакции) |
| Выгрузка | openpyxl |
| Конфигурация | `.env`, ни одного секрета в коде |

Зависимостей ровно три. Бот запускается на любом VPS от 200 ₽/мес и не требует
ни базы данных на отдельном сервере, ни Docker.

## Запуск

```bash
git clone https://github.com/StillBenn/telegram-bot-larisel.git
cd telegram-bot-larisel
pip install -r requirements.txt
```

1. Получите токен у [@BotFather](https://t.me/BotFather).
2. Скопируйте `.env.example` в `.env` и вставьте токен в `BOT_TOKEN`.
3. Запустите бота: `python bot.py` (в Windows можно двойным кликом по `run.bat`).
4. Напишите боту `/whoami`, скопируйте свой ID в `ADMIN_IDS` в `.env` и
   перезапустите — теперь заказы приходят вам, а `/admin` открывает панель.

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `ADMIN_IDS` | нет | ID администраторов через запятую |
| `VIEWER_URL` | нет | ссылка на 3D-конфигуратор |
| `MANAGER_URL` | нет | ссылка на менеджера |
| `SHOP_NAME` | нет | название мастерской в текстах |
| `DB_NAME` | нет | имя файла базы в папке `data/` |

## Проверка

Три набора тестов, все работают на временной базе и без обращений к Telegram:

```bash
python tests/smoke.py        # цены, база, выгрузка, лимиты Telegram — 53 проверки
python tests/flow.py         # весь путь заказа через Dispatcher — 46 проверок
python tests/regressions.py  # разобранные ошибки — 27 проверок
```

`tests/flow.py` поднимает реальный диспетчер со всеми роутерами и мидлварями,
подставляя вместо Telegram поддельную сессию. Так проверяется то, что не видно
в юнит-тестах: порядок роутеров, срабатывание фильтров, доступ к админке,
уведомления администратору и клиенту.

`tests/regressions.py` воспроизводит ошибки, которые уже были в коде и были
исправлены, — чтобы они не вернулись:

| Что проверяется | Чем это было опасно |
|---|---|
| Корзина не меняется во время оформления | клиент подтверждал 42 900 ₽, а заказ создавался на 85 800 ₽ |
| Подпись корзины при подтверждении | то же самое со второго устройства |
| Команда не проходит как имя | в мастерскую падал заказ от клиента «/start» |
| Предел позиций в корзине | 40 сборок — и корзина больше не открывается никогда |
| Обрезка истории заказов | 10 заказов по 6 позиций не влезали в сообщение |
| Формулы в выгрузке | `=HYPERLINK(...)` в имени клиента выполнялся у администратора |
| Часовой пояс | на UTC-сервере даты уезжали на сутки |
| Совпадение текста кнопок | лишний невидимый символ — и «Отменить» молча не работает |

## Структура

```
bot.py                  запуск, логирование, меню команд
app/
  config.py             настройки из .env
  catalog.py            товар, опции, расчёт цены      <- единственный файл для правок каталога
  texts.py              все русские тексты
  keyboards.py          клавиатуры и CallbackData
  states.py             состояния оформления заказа
  db.py                 SQLite: корзина, заказы, статистика
  export.py             Excel и CSV
  middlewares.py        антиспам, регистрация пользователя, доступ к админке
  ui.py                 перерисовка экрана (фото/текст)
  handlers/             common · configurator · cart · checkout · orders · admin · fallback
tests/                  smoke.py, flow.py
assets/                 фото товара (рендер из 3D-конфигуратора)
```

### Решения, которые стоит объяснить

- **Экран сборки — одно сообщение, которое перерисовывается.** В чате не
  копится «хвост» из промежуточных сообщений, и цена всегда видна в одном месте.
- **Каталог описан данными, а не кодом.** Клавиатуры, тексты и расчёт строятся
  из `catalog.py` автоматически: добавить ткань — одна строка.
- **Заказ и очистка корзины — одна транзакция.** Промежуточного состояния
  «заказ создан, но корзина осталась» не существует.
- **Цены в боте и в 3D-конфигураторе совпадают до рубля.** Расхождение здесь
  ломает доверие клиента на первом же заказе.
- **Корзина живёт в базе, а не в памяти.** Перезапуск бота не теряет собранное.
- **Стандартный `sqlite3` вместо ORM.** Три таблицы и десяток запросов —
  внешняя зависимость стоила бы дороже, чем экономила. Блокирующие вызовы
  уходят в поток через `asyncio.to_thread`, event loop не встаёт.
